01Project Vision

Why this system exists and what it refuses to do

Most trading-bot demos fake something — a fill price, a win rate, a backtest result. This system was built around the opposite constraint: every price, fee, and profit shown anywhere in the system must be real or explicitly absent. If a live price can't be fetched, the system skips that unit of work and says so — it never substitutes a guessed or stale number and presents it as current.

1.1 What It Does

Continuous Paper Trading
Runs a background loop that polls live Binance prices every 5 minutes, evaluates three independent strategies per symbol, and opens/closes simulated positions with real transaction costs applied.
Earned Strategy Access
No strategy trades live by default. Each must first pass a real backtest against historical candles (Sharpe ratio, max drawdown, and minimum trade count thresholds) before it is allowed to open a position.
Continuous Self-Correction
Every 72 cycles (~6 hours) the system re-runs the same backtest gate against fresh data. A strategy that stops working is demoted; one that starts working is promoted — automatically, without manual intervention.

1.2 What It Does Not Do

It does not place real orders, hold real funds, or authenticate against any exchange account. There is no order-routing code, no withdrawal capability, and no API key anywhere in the system — the market-data endpoints used are public and unauthenticated.

02System Architecture & Technology Stack

Two decoupled processes, one shared datastore

The trading loop and the dashboard are independent OS processes that never call each other directly — they communicate only through a shared SQLite file. The loop is the sole writer; the dashboard is a read-only consumer plus one live price call of its own for unrealized P&L display.

03Signal & Risk Pipeline

Three deterministic strategies, gated by a real backtest, sized by real edge

3.1 Strategy Layer — Deterministic, No Runtime Inference

Each strategy is a pure function of price history: signal(closes) -> "buy" | "sell" | "hold". No model inference, no external calls — same input always produces the same output.

SMA Crossover — fast=10, slow=30 
if fast_prev <= slow_prev and fast_now > slow_now: return "buy"
if fast_prev >= slow_prev and fast_now < slow_now: return "sell"
RSI Threshold — period=14, oversold=30, overbought=70 
if rsi_prev <= oversold and rsi_now > oversold: return "buy"
if rsi_prev >= overbought and rsi_now < overbought: return "sell"
Momentum — lookback=20, threshold=0.0 
ret = (closes[-1] - closes[-(lookback+1)]) / closes[-(lookback+1)]
if ret > threshold: return "buy"
if ret < -threshold: return "sell"

3.2 Backtest Pass Gate

A strategy earns live trading rights only if it clears all three thresholds on real historical data:

Pass Criteria 
passed = sharpe > 0 and max_drawdown < 0.5 and num_trades >= 2

3.3 Half-Kelly Position Sizing

Position size is derived from each strategy's own real backtested win rate and payoff ratio — never a fixed percentage of the account:

Kelly Fraction 
def kelly_fraction(win_rate, payoff_ratio):
    p, q, b = win_rate, 1 - win_rate, payoff_ratio
    if b <= 0: return 0.0
    return max(0.0, min((b*p - q) / b, 1.0))

def position_size(equity, win_rate, payoff_ratio, fraction=0.5):
    return equity * kelly_fraction(win_rate, payoff_ratio) * fraction

04Self-Improvement Layer

The system's standout feature — it re-earns its own trading rights on a schedule

A one-time vetting decision at startup is not trusted forever. Every 72 cycles (~6 hours at the 5-minute poll interval) every strategy is re-backtested against a fresh 500-candle window. Strategies that stop performing are automatically benched; strategies that start performing are automatically re-admitted — with no manual review step.

Periodic Re-vetting 
REVET_INTERVAL_CYCLES = 72  // 6 hours at the 300s poll interval

def maybe_revet(conn, cycles_since_vet, approved_strategies, ...):
    cycles_since_vet += 1
    if cycles_since_vet < revet_interval:
        return approved_strategies, cycles_since_vet
    try:
        new_approved, _ = vet_fn(conn)
    except (PriceFetchError, RequestException):
        // keep current approvals, retry next interval — never crash
        return approved_strategies, 0
    return new_approved, 0

4.1 Demotion Without Abandonment

A demoted strategy is blocked from opening new positions, but it is still evaluated every cycle so any position it already holds can close on its own exit signal — no forced liquidation, no orphaned trades left unmanaged on the books.

4.2 Fault Isolation

A failed re-vet (network error, malformed response) never crashes the loop and never silently approves everything by default. It keeps the current approval set and retries at the next full interval — the same fail-safe posture applied to every network call in the system.

5.2 Failure Handling

Every live price call on the dashboard is wrapped to catch both API-level errors and raw network failures (DNS, connection refused, timeout). On failure, the affected section shows an explicit warning banner and falls back to the last known entry price for display purposes — the page never crashes and never silently substitutes a fabricated number.

5.3 Optional Auto-Refresh

An opt-in toggle (default off) reloads the page every 30 seconds via a plain HTML meta-refresh tag — no polling loop, no additional dependency, no blocking of the underlying script thread.

6.2 Full Cycle

Startup vetting → seed price history → poll live prices (skip symbol on failure, never substitute a stale price) → append to history → build evaluate-set (approved strategies + any demoted strategy with an open position) → evaluate signals → open on approved buy signals sized via half-Kelly → close on any sell signal regardless of approval status → log equity → check re-vet interval → sleep 300s → repeat.

7.4 Future Scope

A leverage/margin engine (isolated margin, long/short, real funding rate) has been built and independently tested but is not wired into the live loop. An episode/reset game-loop layer was scoped but not implemented. Both remain deliberately out of the current system to keep the live bot's behavior simple and auditable.

Conclusion Every number in this report — the fee rates, the backtest thresholds, the live equity figure, the test count — was pulled directly from the running codebase and database at the time of writing, not written from memory or estimated. That is the operating principle the entire system was built against: never present a fabricated price, fill, or profit as if it were real.
